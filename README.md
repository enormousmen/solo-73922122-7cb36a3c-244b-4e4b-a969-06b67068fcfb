# Redis 会话迁移台

换 Redis 节点时让已登录用户沿用原会话：FastAPI 迁移页 + 两个 Redis（旧库只读回读、新库为准），支持分批搬运、暂停写入、暂停期间查询/续期/注销，搬运完成后可从网页关闭旧库回读并断开旧库。

## 快速开始

```bash
docker compose up --build
# 打开 http://localhost:8000
```

compose 会启动 4 个服务：

| 服务 | 说明 |
|---|---|
| `redis-old` | 旧节点（宿主端口 6380）。挂载 `redis-old/users.acl`：应用账号 `app` 只有读权限，从服务端强制“搬运期间旧库只读” |
| `redis-new` | 新节点（宿主端口 6381） |
| `seed` | 一次性容器：向旧库预置 25 个样例会话（24 个 2 小时有效 + 1 个 45 秒短会话 `short-lived`） |
| `web` | FastAPI 迁移页（端口 8000） |

## 网页操作

1. **会话查询**：输入会话 ID（如 `s01`、`short-lived`）→ 显示有效状态、到期时刻、来源（new/old）。搬运前未搬入的会话自动回旧库读取，已登录用户无感。
2. **分批搬运**：
   - `开始/继续自动搬运`：后台逐批 SCAN 旧库 → 写入新库；
   - `暂停`：当前批次处理完后停下；
   - `读取一批（暂停写入）` / `写入持有批次`：手动单步，精确复现“读到一批后暂停写入”；
   - `重置搬运`：计数与游标清零，用于验证重试安全。
3. **暂停期间**：查询、续期（默认 +1800s，可改）、注销均照常；只写新库。
4. **关闭旧库回读**：搬运完成（状态 done）后才允许点击；关闭后 `docker stop redis-old`，查询、续期、注销仍全部正常。

## 关键设计（不变式）

- **读路径**：先查新库（含“已注销”墓碑），未命中且回读开启时才回旧库 —— “尚未搬入且未在新库改动的会话从旧库读取”，“续期或注销后查询以新库为准”。
- **写路径**：续期/注销只写新库；旧库应用侧不写 + ACL 服务端强制只读。
- **搬运写入**：`SET key val PX <剩余毫秒> NX` —— 保留原到期时刻；已存在（续期新值/注销墓碑/已搬过）一律跳过，**继续或重试搬运都不能把新库改回旧状态**。
- **过期不恢复**：批次读出时记录 PTTL 与时刻，写入时按已流逝时间扣减；暂停期间过期的会话直接丢弃，绝不写入。
- **游标提交**：SCAN 游标在对应批次写入成功后才存入新库 `migration:state`，暂停/重启不丢会话（持有批次丢失会重扫）。
- **注销墓碑**：值为 `{"revoked":true,...}`，TTL = 原剩余寿命（原到期时刻后自动消失，此时旧库会话本身也已过期）。

## API（页面按钮即调用这些接口）

```
GET  /api/sessions/{sid}                 查询有效状态/到期时刻/来源
POST /api/sessions/{sid}/renew           续期 {"extend_seconds": 1800}
POST /api/sessions/{sid}/revoke          注销（写墓碑）
GET  /api/sessions                       新旧库合并列表
GET  /api/migration/status               状态/计数/持有批次/日志/连通性
POST /api/migration/start | pause        自动搬运 / 暂停
POST /api/migration/step/read|write|discard  单步读一批 / 写持有批次 / 丢弃
POST /api/migration/reset                重置计数与游标
POST /api/migration/fallback/disable     关闭旧库回读（仅 done 后可用）
```

## 实测结果

本环境无 Docker，用源码编译的 Redis 7.2.5 双实例（6380=旧带 ACL / 6381=新）+ 同一应用代码实测，`scripts/integration_test.py` 全程通过网页同款 HTTP API 驱动：

- **ACL 只读**：`app` 账号 `SET`/`DEL` 返回 `NOPERM`，`GET`/`PING` 正常 ✅
- **before-kill 阶段 40 项全部 PASS**：
  - 搬运前 `s01` 来源=old；未完成时关闭回读被拒(409)；不存在会话续期/注销被拒(409)
  - 读取一批 → paused，持有 5 条；暂停期间续期（+1800s，实测 dt=1800s）、注销、重复注销 409、旧库会话续期/注销均成功
  - 写入持有批次：跳过已存在 2 条（续期+注销），新搬 3 条
  - `short-lived` 在持有批次中暂停至自然过期 → 写入时过期丢弃，查询仍无效（未复活）
  - 自动搬运至完成：`migrated=20 skipped=4 expired=1`；`s03` 到期时刻漂移 0.0s
  - 重置后重跑：`migrated=0 skipped=24`，续期/注销状态未被改回
  - 关闭回读成功，查询走新库
- **after-kill 阶段 11 项全部 PASS**（旧库进程已终止）：状态可查、已搬入会话有效、续期正常、注销仍无效、过期会话不恢复、陌生会话 not-found、页面可打开
- **自动模式暂停**：pause 在批次边界生效，恢复后跑完 `migrated=25`
- **旧库零改动**：搬运前后旧库全部键与值逐字节 diff 一致 ✅
- 应用日志无错误；`docker-compose.yml` 通过 YAML 解析校验

- [ ] 单进程单 worker：多副本部署时迁移引擎需要分布式锁
- [ ] 旧库断开且回读仍开启时，未搬入会话查询返回 `old-unavailable` 视为无效（ fail-closed）；如需 fail-open 可加配置
- [ ] 样例会话为 JSON 字符串值；真实会话若含其他类型（hash 等）需扩展搬运编解码
